# SillyTavern Base64 整段转换

一个独立、纯前端的 SillyTavern 扩展。轻点功能只处理当前草稿；另提供两个默认关闭、由用户明确启用的请求/响应适配开关。

## 功能

- 轻点半透明 `B64` 悬浮窗：将输入框中的整段文字按 UTF-8 编码为标准 Base64，并替换原文。
- 正在编辑已发送消息时，优先转换当前消息的编辑草稿；没有消息编辑框时才处理底部发送输入框。
- 长按悬浮窗约 500ms：只打开更多选项，不执行转换；菜单中可以撤销最近一次转换。
- 长按菜单可选择“整段”或“分块”；分块默认每 8 个 Unicode 字符，每块独立 UTF-8 Base64，并输出为 `1/N:...`。
- 可选“结构化封装”：把完整原文按同一块长度放入清楚可见的 JSON envelope，包含 `format`、`version`、`encoding` 和有序 `chunks`。
- 可选“保留技术格式”：只保留明确的围栏代码、行内代码、Markdown 链接和 HTML 标签，其他正文照常编码。
- 拖动悬浮窗：适配鼠标和手机触摸；移动超过阈值会取消轻点和长按动作。
- 支持中文、emoji、空格、Tab 和换行；转换前会在本地解码并逐字校验。
- 空输入不操作；连续误点不会把刚生成的 Base64 再编码一次。
- 转换后只要手动改过输入框，扩展撤销就会立即失效，避免覆盖新内容。
- 整段模式对长文本采用内部字节批处理，但输出仍是一整段标准 Base64；只有主动选择“分块”时才生成编号块。
- 可选“发送前处理”（默认关闭）：只在普通发送时，将最后一条用户消息临时换成清楚可见、可逆的 `BASE64-SCATTER/1` 分块格式，让 SillyTavern 组装请求；请求数据就绪后立即恢复原消息，不保存临时文本到聊天历史。
- 可选“响应正文提取”（默认关闭）：只处理 SillyTavern 的 OpenAI 兼容聊天生成接口；当普通正文为空、而工具参数中确实存在 `body`、`content`、`text` 或 `response` 字符串时，将它作为普通正文显示。
- 长按菜单中的“实际发送预览”直接调用与临时发送相同的转换函数，不使用另一套近似规则；发送前处理生效时，悬浮按钮会显示绿色状态点。

默认设置仍是“整段 + 不保留技术格式”，与 1.1.0 行为一致。菜单中的配置只保存在当前浏览器本地。启用分块时，编号块不能合并后当作一个 Base64 解码，必须逐块解码后按编号拼接。扩展会在替换前逐块本地还原并核对原文。

结构化封装始终编码完整原文，因此不会应用“保留技术格式”；菜单会明确显示这一点。封装内容会完整显示在当前输入框或消息编辑框中，扩展不会自动发送、保存、隐藏恢复或修改任何网络请求。该模式只是通用可逆文本格式，不保证改变任何服务的审核结果。

发送前处理与上面的手动输入框转换相互独立。它仅支持普通发送，不作用于重新生成、继续、换页、静默生成或 dry-run。临时替换会在 `generate_after_data` 阶段恢复，并在停止、结束、切换聊天和扩展卸载时执行兜底恢复；如果同一条消息被并发改动，扩展不会覆盖新内容。

响应正文提取的准确支持范围是 `POST /api/backends/chat-completions/generate`，支持 JSON、SSE 和 NDJSON 响应。普通文本、已有正文、拒绝正文、错误、未知结构以及其他接口保持原样；不会修改 `finish_reason`、强制工具调用、模型路由或采样参数。流式工具参数可跨网络 chunk 与 SSE 事件拼接，并且只注入一次正文。

> Base64 只能保证编码与解码可逆，不能保证聊天模型一定能正确理解 Base64 内容。

## 安装（推荐）

1. 在 SillyTavern 打开“扩展”面板。
2. 点击“安装扩展”，粘贴仓库地址：
   `https://github.com/hrholic/SillyTavern-Base64-Composer`
3. 按界面提示完成安装，然后刷新页面；如扩展显示为停用，请手动启用“Base64 整段转换”。

## 手动安装（Android Termux / 桌面）

1. 解压发布的 ZIP，得到 `SillyTavern-Base64-Composer` 文件夹。
2. 把整个文件夹放到 SillyTavern 的当前用户扩展目录：
   `SillyTavern/data/<你的用户目录>/extensions/`
3. 确认最终路径是：
   `SillyTavern/data/<你的用户目录>/extensions/SillyTavern-Base64-Composer/manifest.json`
4. 重启 SillyTavern，或刷新浏览器页面；如扩展管理页显示为停用，请手动启用“Base64 整段转换”。

常见的 Termux 安装根目录是：
`/data/data/com.termux/files/home/SillyTavern/`

不同安装方式的根目录可能不同；`<你的用户目录>` 也可能是 `default-user` 或你自己创建的用户目录。

## 使用

- 先在 SillyTavern 输入框中写好原文，再轻点 `B64`。
- 长按 `B64` 约 500ms 展开菜单；长按后松手不会转换。
- 需要请求适配时，在长按菜单中分别开启“发送前处理”或“响应正文提取”；两个开关初始均为关闭。
- 开启“发送前处理”后，可展开“实际发送预览”查看将要进入请求装配的完整文本。
- 在菜单中点“撤销转换”可恢复最近一次原文。
- 按住并移动 `B64` 可拖动；位置会保存在当前浏览器中。

## 隐私与范围

- 不创建额外网络请求、无第三方依赖，也不触发发送按钮。
- 只有用户主动开启响应正文提取时，扩展才临时包装浏览器 `fetch`，且只读取上述聊天生成端点的响应；关闭时会移除包装。
- 不读写聊天记录，只替换当前消息编辑 textarea 或 `#send_textarea` 的草稿值；不会自动点击保存、发送或取消。
- 发送前处理只在内存中临时改写当前普通发送的最后一条用户消息，并在请求装配后恢复；不会调用聊天保存接口。
- 不会自动更新（`auto_update: false`）；更新由用户自行确认和执行。

## 本地测试

需要 Node.js 20 或更高版本：

```bash
npm test
```

自动测试覆盖 UTF-8/Base64 往返、中文、emoji、混合换行与空格、长文、空输入、防重复、撤销安全、轻点/长按/拖动互斥、鼠标与模拟触摸、移动视口边界、临时消息恢复、接口限定、JSON 正文提取和跨 chunk 的 SSE 解析。

这些测试是 Node.js 中的逻辑与交互状态模拟，并不等同于在真实 SillyTavern、Android Chrome 或桌面浏览器中的人工安装测试。
